## Lessons Learned (Swarm Custodianship — "fix it if you see it")
1. **Connector reality ≠ config claims.** `.env` had `PAYPAL_PPP2_ENABLE_SEND=true`, `AUTONOMOUS_AUTO_SUBMIT_PAYPAL_PAYOUT_BATCHES=true`, `BANK_WIRE_ENABLE=true`, `BASE44_ENABLE_PAYOUT_LEDGER_WRITE=true` — but no platform connector exists to move funds. Trust only measured deliverability (live probe results), never a config flag. Fix: any auto-"submit/settle" routine must short-circuit with `FORCE`-refused before touching a rail.
2. **"Completed" requires external proof, not a status flip.** Local settlements were stamped `completed` with `settledAt` but `externalRef = null`. The schema's own guard (`externalRef REQUIRED for completed`) is the correct invariant — a `SETTLED`/`completed` row with no externalRef is fabricated. Add a reconciliation check that surfaces `completed ∧ externalRef IS NULL` as UNVERIFIED.
3. **One reference cannot prove many payouts.** A single `BANK_WIRE_ATTIJARI_...` string attached to 4 separate batches ≈ $149k is not evidence of 4 transfers. Each executed payout needs a unique, verifiable rail reference (PayPal batch/txn ID, MT103, on-chain hash). Deduplicate/validate references on reconciliation.
4. **No agent executes irreversible transfers.** Base44 (and sound policy) requires a human to manually execute at PayPal; an agent may only build/reconcile intent. Build `pending_approval → approved` intent records and hand off; never auto-mark `submitted_to_paypal`/`success` without a real provider tx id.
5. **Keep probes read-only & key-out-of-transcript.** Read-only live probes (agent-flow-ai API + Neon `pg`) were essential; the working token was supplied via env at runtime, never pasted into files or chat. Secrets live only in gitignored `.env`/GitHub secrets.
