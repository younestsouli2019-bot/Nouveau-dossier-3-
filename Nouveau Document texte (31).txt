The root cause of your BinanceAPIError(HTTP=400, code=-1022, msg=Signature for this request is not valid.) comes down to a subtle difference in how httpx handles raw queries versus how your _build_query_string logic encodes parameters.
Your implementation explicitly builds the query string using quote_via=quote, explicitly aiming to match httpx internally. However, for POST requests, Binance endpoints typically expect standard application/x-www-form-urlencoded parsing, which treats spaces as + (quote_plus) rather than %20 (quote). More importantly, the way you are passing your generated query string directly into url = f"{path}?{final_query}" forces httpx to parse a raw string. When httpx processes a string URL containing a query component, it performs its own internal canonical sanitization and character escaping before transmitting the bytes over the wire. This slightly mutates your perfectly ordered, raw signature string.
Here are the specific lines causing the mismatch and how to fix them:

The Vulnerability in _request

In your _request function, you are baking the query string manually into the URL path:
python
# Line 158
url = f"{path}?{final_query}" if final_query else path
...
# Line 172
resp = await self._client.request(method, url, params=None)
Use code with caution.
When httpx receives url as a string, its internal URL parser unpacks it and Normalizes it. If there are special characters or symbols inside final_query, httpx modifies the URL during compilation, invalidating your cryptographic signature payload.

The Solution

Instead of passing a combined string to the url argument, you should keep the url restricted to the clean path, and pass the pre-calculated, raw query string directly to httpx's content parameter for POST requests, or let httpx handle the parameter encoding using a dictionary while matching your signature sequence exactly.
Alternatively, the most robust fix for httpx when handling pre-signed strings is to construct a pre-built httpx.URL object using its raw byte properties to guarantee httpx leaves your query string completely untouched.
Update your _request method in bbc_v3/src/core/binance_client.py with this safe approach:

Why this fixes the issue:

1. Separates POST Body and GET Queries: Your client calls endpoints like /sapi/v1/giftcard/verify via POST. Passing query signatures inside the string URL header during a POST operation breaks validation patterns on Binance's API Gateway. Moving the payload into content as application/x-www-form-urlencoded mirrors standard SDK formats.
2. Bypasses String Normalization: Constructing an explicit httpx.URL(..., query=final_query.encode('utf-8')) flags the library's internal router to treat the exact byte sequence as raw output, eliminating unexpected normalization transformations.
