## Legend

- **ID**: Unique task ID (S#-T## — slice number, task number)
- **Priority**: P0 — CRITICAL (do FIRST; without these we have security/structural fail-closed risk), P1 — HIGH (core architecture / AC rule requirements), P2 — MEDIUM (AC rubric requirements / nice-to-haves that evaluator judges quality on)
- **AC**: Comma-separated list of AC IDs covered from spec.md §6
- **Type**: rule | rubric (matches AC type; rule tasks are binary pass/fail; rubric tasks are evaluator-judged)
- **Test / Verification Method**: How this task is PROVEN completed — always automated where possible, manual evaluator where needed
- **Fail-Closed Guard**: What gate prevents merging/shipping if this task is incomplete
- **Expected Artifacts**: Files written / modified
- **Blocking Dependencies**: Tasks that must complete first
